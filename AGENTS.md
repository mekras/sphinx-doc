# Инструкции для агента

Проект использует `ai-dev-team`.

## Входной протокол

Перед ответом, вопросом, исполнением или передачей работы по каждому элементу
корневого входа открой `.agents/skills/ait-routing/SKILL.md`. Если путь недоступен,
используй `.claude/skills/ait-routing/SKILL.md`. Если оба файла отсутствуют,
остановись и сообщи о блокере.

Следуй открытому навыку, включая подготовку первого ответа. Первым сообщением
покажи маршрут со строками «Режим менеджера», «Причина» и «Маршрут».

## Проектные источники

- Корень проекта — каталог этого `AGENTS.md`, репозиторий `mekras/sphinx-doc`.
- Концепция проекта — вводный абзац [README.md](README.md), начинающийся словами
  «Проект предоставляет авторам документации».
- Проверяй необходимость обновления [CHANGELOG.md](CHANGELOG.md) через
  `.agents/skills/ait-changelog/SKILL.md`.
- Граф влияния проекта — `.ai-dev-team/project-impact.json`. После изменения
  проектных файлов применяй `ait-impact-analysis`: проследи полное влияние
  и выполни профильную проверку каждой затронутой части. Новый несопоставленный
  путь требует дополнить граф до завершения задачи. Установленные проекции
  `.agents/` и `.codex/` проверяются через `apm audit --ci`.

## Приоритеты проектных решений

При выборе проектных решений соблюдай порядок приоритетов: надёжная сборка
и совместимость → простота для автора документации → предсказуемость обновлений
→ обратимость изменений → новые возможности.

## Проверки пользовательских команд

При изменении пользовательских команд сборки или предпросмотра заранее назови
обязательные автоматические проверки затронутого сценария. Для команд сборки
документации обязательны успешные сборки HTML и PDF. Изменение готово только
после успешного выполнения названных проверок. Недоступность среды блокирует
готовность изменения. Структурная проверка файлов не заменяет запуск сценария.

## Внесение изменений

- Ограничивай проектные изменения областью поручения. Не изменяй другие проекты,
  репозитории и исходники зависимостей, если это не входит в поручение.
- Расположение файла вне каталога проекта само по себе не запрещает необходимые
  для поручения операции. Сохраняй предусмотренную поручением операцию. Если ей
  мешает действующее ограничение, обозначь конфликт до выбора замены.
- Сохраняй посторонние изменения.

## Git

- Сообщения коммитов оформляй по схеме Pro Git: краткий заголовок на русском
  с прописной буквы, описывающий завершённый результат, например «Добавлена
  концепция проекта». При необходимости после пустой строки поясняй причину
  изменения. Подготавливай и проверяй сообщения через `ait-commit-messages`.
- Добавляй в индекс Git только файлы и фрагменты, созданные или изменённые агентом
  в рамках текущей задачи.
- Сохраняй состояние индекса и рабочей копии, существовавшее на момент начала
  задачи. Если файл уже содержал изменения и собственные фрагменты нельзя надёжно
  отделить, не добавляй файл целиком в индекс и сообщи об этом.
- Не выполняй коммит и отправку изменений без явной просьбы пользователя.
